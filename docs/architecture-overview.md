## 后端架构

### 分层架构

后端采用经典的分层架构模式，职责清晰、便于维护：

```
┌─────────────────────────────────────────────────────────────┐
│                      Controller 层                          │
│                   (HTTP 请求处理)                            │
│  • 接收 HTTP 请求                                            │
│  • 参数校验 (@Valid)                                         │
│  • 调用 Service 层                                           │
│  • 返回 Result<VO> 响应                                      │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                       Service 层                            │
│                    (业务逻辑层)                              │
│  • 实现业务逻辑                                              │
│  • 事务管理 (@Transactional)                                 │
│  • 调用 Mapper 层                                            │
│  • 调用其他 Service (跨领域)                                  │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                       Mapper 层                             │
│                    (数据访问层)                              │
│  • MyBatis XML 映射                                          │
│  • 数据库 CRUD 操作                                          │
│  • 无业务逻辑                                                │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                      Database 层                            │
│                    (PostgreSQL)                             │
└─────────────────────────────────────────────────────────────┘
```

### 数据流转

```
Request (前端) → Controller → Service → Mapper → Entity → Database
                                          ↓
Response (前端) ← Result<VO> ← Converter ← DTO
```

### 各层职责

#### Controller 层

```java
@RestController
@RequestMapping("/api/posts")
@RequiredArgsConstructor
public class PostController {
    private final PostService postService;
    private final PostConverter postConverter;

    @PostMapping
    @PreAuthorize("isAuthenticated()")
    public Result<PostVO> createPost(@Valid @RequestBody PostCreateRequest request) {
        PostDTO dto = postConverter.toDTO(request);
        Post post = postService.create(dto);
        return Result.success(postConverter.toVO(post));
    }
}
```

**职责**：
- 处理 HTTP 请求/响应
- 请求参数校验（`@Valid` 或 `@Validated`）
- 调用 Service 层方法
- 结果转换为 VO
- 返回统一格式的响应

#### Service 层

```java
@Service
@RequiredArgsConstructor
public class PostService {
    private final PostMapper postMapper;
    private final UserService userService; // 跨域调用

    @Transactional
    public Post create(PostDTO dto) {
        // 业务逻辑
        Post post = new Post();
        BeanUtils.copyProperties(dto, post);
        postMapper.insert(post);
        return post;
    }
}
```

**职责**：
- 实现业务逻辑
- 事务管理（`@Transactional`）
- 调用 Mapper 进行数据访问
- **规则**：只直接使用同名的 Mapper；通过其 Service 访问其他 Mapper

#### Mapper 层

```xml
<mapper namespace="com.bryan.platform.mapper.PostMapper">
    <select id="selectById" resultMap="BaseResultMap">
        SELECT * FROM post
        WHERE id = #{id} AND deleted = 0
    </select>

    <update id="updateById">
        UPDATE post
        <set>
            <if test="title != null">title = #{title},</if>
            <if test="content != null">content = #{content},</if>
            updated_at = CURRENT_TIMESTAMP
        </set>
        WHERE id = #{id} AND deleted = 0
    </update>
</mapper>
```

**职责**：
- 仅数据访问
- MyBatis XML 映射
- 无业务逻辑

### 数据对象类型

| 类型 | 用途 | 示例 |
|------|------|------|
| **Request** | 前端 → Controller 输入 | `PostCreateRequest` |
| **DTO** | 层间数据传输 | `PostDTO` |
| **Entity** | 数据库实体 | `Post` |
| **VO** | 后端 → 前端输出 | `PostVO` |

### 状态管理

```typescript
// stores/user.ts
export const useUserStore = defineStore('user', () => {
    // State
    const token = ref<string>('')
    const userInfo = ref<UserInfo | null>(null)
    const userProfile = ref<UserProfile | null>(null)

    // Getters
    const isAuthenticated = computed(() => !!token.value)
    const isAdmin = computed(() => userInfo.value?.roles?.includes('ROLE_ADMIN'))

    // Actions
    async function login(loginData: LoginRequest) {
        const res = await loginApi(loginData)
        token.value = res.data
        await fetchUserInfo()
        return res
    }

    return { token, userInfo, isAuthenticated, isAdmin, login }
}, {
    persist: true  // 持久化到 localStorage
})
```

## 安全架构

### 认证流程

```
┌─────────┐                              ┌──────────────┐
│  Client │  ───── POST /api/auth/login ───→ │   AuthController  │
│         │                              └──────┬───────┘
│         │                                     │
│         │                              ┌──────▼───────┐
│         │                              │  AuthService │
│         │                              └──────┬───────┘
│         │                                     │
│         │                              ┌──────▼───────┐
│         │                              │  UserDetailsService
│         │                              └──────┬───────┘
│         │                                     │
│         │                              ┌──────▼───────┐
│         │                              │  JwtUtil     │
│         │                              └──────┬───────┘
│         │                                     │
│         │  ←──── { token: JWT } ──────────────┘
│         │
│         │  ───── 后续请求 (Authorization: Bearer JWT) ─────→
│         │
└─────────┘
```

### 安全机制

| 机制 | 实现 | 说明 |
|------|------|------|
| **JWT 认证** | `JwtAuthenticationFilter` | Token 解析与验证 |
| **方法级授权** | `@PreAuthorize` | 细粒度权限控制 |
| **密码加密** | BCryptPasswordEncoder | 用户密码加密存储 |
| **登录保护** | 失败次数限制 | 5次失败后锁定30分钟 |
| **CORS** | 配置白名单 | 开发/生产环境分离 |

## 扩展性设计

### 水平扩展

- **无状态设计**：应用层无状态，支持多实例部署
- **会话共享**：JWT 替代 Session，Redis 可集群
- **数据库读写分离**：可配置主从复制

### 功能扩展

- **插件化架构**：通过配置添加新的 LLM Provider
- **算法参数化**：算法权重可配置化
- **模块解耦**：Controller-Service-Mapper 分层便于功能扩展
